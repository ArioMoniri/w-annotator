# Decisions

A running record of decisions made about W Annotator: by the user, in a `grill-me` session, by the council, or by an agent that had to choose in order to continue.

How to use it:

- Add one row per decision, newest at the bottom. Use the date the decision was made (YYYY-MM-DD).
- Write the decision as a plain statement someone can act on. Give the reason in one line.
- Never edit or delete an earlier row. To change a decision, add a new row that says which one it supersedes.
- Check here before asking a question. If it is answered, do not ask again.

| 2026-11-19 | Should the app have a light theme, and what happens to the image? | Three appearance modes: Light, Dark and System (default, follows the OS live). Viewports, the gaps between them and everything drawn over the image stay dark in both themes. | Requested in issue #1. A black surround is how images are read; a bright frame or bright overlays would change perceived contrast. |
| 2026-11-19 | Which light palette? | The optional light palette in `DESIGN.md` section 3, with `--text-3`, `--accent`, `--ok`, `--warn`, `--danger` darkened and `--border-control` added. | As drafted, several pairs fell below 4.5:1 for text or 3:1 for control borders. | 2026-11-19 | How do reports from inside the app reach GitHub? | The app composes the report and opens GitHub's pre-filled new-issue form in the browser; the user submits it as themselves. New dependency: the official Tauri opener plugin, allowed to open only URLs under `https://github.com/ArioMoniri/w-annotator/`. | A GitHub token in the app could be extracted from the binary. The app itself sends nothing, so the no-telemetry rule holds. |
| 2026-11-19 | Where do preferences live? | One Settings dialog (file menu, empty state, `Mod+,`) with five sections shown one at a time: Profile, Appearance, Shortcuts, Files, Help. Changes apply as they are made. The shortcut sheet moved into it; `?` opens Settings at Shortcuts. | Requested in issue #7. One place is easier to find than a growing file menu. |
| 2026-11-19 | How does a name change reach a room? | A `rename` peer message (`{ t, from, name }`). The relay forwards it untouched. Someone who has renamed re-sends it when a newcomer joins, because the relay introduces people by the name they connected with. | Requested in issue #7. No relay change needed; the payload is still only the display name. |
| 2026-11-19 | May the welcome tour loop an animation, given "nothing loops"? | Yes, only for the small hint drawings inside the tour card, 2 s, `transform` and `opacity`, still under reduced motion. Nothing else loops. | Asked for in issue #7 to show a gesture; it never touches the image and stops when the tour does. |
| 2026-11-19 | What does the tour open as a sample? | A 64 × 64 × 48 synthetic phantom and two-label mask generated in `src/sample.ts`. No image file is bundled. | No patient data in the app; adds almost nothing to the bundle. |
| 2026-11-19 | Should the tour's sample be a real scan? | Yes. One LUNA16 chest CT (LIDC-IDRI) with its lung mask, cropped to the body and halved in-plane, is shipped in `public/sample/` (256 × 176 × 121, 7.1 MB) and opened through the normal open path on a lung window. The phantom above stays as the fallback when those files cannot be loaded, and for tests. This replaces the row above. Attribution is in `public/sample/ATTRIBUTION.md` and Settings → Help. | A phantom does not show what the app is for. LUNA16 is CC BY 4.0 and LIDC-IDRI CC BY 3.0, so the scan can be redistributed with attribution; PI-CAI and PANORAMA are non-commercial and were not used. Issue #17. |
| 2026-11-19 | Autosave: what happens to new edits while a found recovery copy is waiting for Restore or Discard? | Autosave pauses until the user chooses, and the bar says so once there are new edits. "Save mask" and "Don't save" leave a waiting copy alone. | Writing would silently replace the work the bar is offering. Issue #8. |
| 2026-11-19 | Autosave: how is "the same image" recognised, and how is "newer than what is on screen" decided? | By a fingerprint of the grid, voxel type and a hash of 4 096 sampled voxels; no name or path. A copy is offered when it differs from the mask on screen. File dates are not compared. | Saving deletes the copy, so any copy that exists was made after the last save in this app; the web build cannot read a file's date without changing `src/io`. Issue #8. |
| 2026-11-19 | Autosave: can the desktop app offer to reopen the image of a recovery copy? | Yes, through a fifth command, `recovery_image(key)`. The path is recorded only for a file the user chose in the app, stays in the app data folder, and only the file name goes back to the web side. Today that covers files opened with the app from the system; files picked in the window have no path. | The four commands in the brief cannot read a file from an earlier run. Issue #8. |
| 2026-11-19 | Autosave: what does switching it off at startup mean? | Off means no recovery copies on this device: any that exist are removed, also when the setting was changed outside the app. | Recovery copies hold patient data; "off" should not leave some behind. Issue #8. |

| 2026-11-19 | How are the views laid out? | Five layouts (2 × 2, 1 large + 3 stacked, 3 side by side, 2 side by side, single), any view in any pane, never the same view twice. Panes are pixel rectangles from `src/viewer/layout.ts`, set by script; the four viewports are created once and only moved, sized or hidden. | Issue #19. The CSS-grid maximise came out as a strip in WebKit. Keeping the viewports alive keeps slice, zoom, window, mask and tools across every change. |
| 2026-11-19 | What stays fixed when a view changes size? | Millimetres per screen pixel and the point at the centre. A resize never refits. | Issue #19. Cornerstone keeps the camera's parallel scale, which is tied to the view's height, so a taller view magnified the image. |
| 2026-11-19 | Can the planes be rotated (oblique MPR)? | No. Reference lines can be dragged to scroll a plane; they cannot be turned. | The review council advised against free rotation: it invites left/right errors in a mask editor. Out of scope for issue #19. |
| 2026-11-19 | Which keys pick a layout? | `Mod+1` to `Mod+5`, rebindable. | Plain digits already pick segments. |
| 2026-11-19 | How does the 3D view draw the mask? | As solid segments with no outline, whatever the opacity and outline settings of the slice views. | With the outline on, Cornerstone's label mapper draws a single cut through the volume, so the 3D view showed one slice of each segment and nothing of a segment off that slice. |
| 2026-11-20 | Several masks: which one is edited, and what are the others? | One mask is active; tools, undo, the segments list, save, autosave and rooms work on it alone. The others are read-only outlines in one neutral colour each, on the slice views only. A newly opened mask becomes the active one and the previous one stays open, unless it was the untouched empty mask, which makes way. At most four. Issue #20. | Opening a mask has always meant "edit this one"; keeping the old one open means nothing is lost. Each mask costs 150 to 300 MB at 512 × 512 × 300. |
| 2026-11-20 | Several masks in a room? | Only the room's mask is editable. A mask opened while in a room is a local outline and is never sent; switching the active mask and closing the room's mask are refused with a message. Issue #20. | The room protocol carries one mask. |
| 2026-11-20 | Several masks and autosave? | The recovery copy belongs to the active mask. Closing the image warns by name about other masks with unsaved edits. Issue #20. | Copies are keyed by image, one per image. |
| 2026-11-20 | Can the image be hidden from the Files list? | No. It can be dimmed (drawn at 35 %); voxel values and the window are untouched. Issue #20. | An overlay with no image under it invites mistakes. |
| 2026-11-20 | When does opening an image replace the current one without asking? | Only when asked for by name (Open image) with nothing unsaved. A dropped or handed-over image always asks, and offers "Add as mask" when its values could be labels. Issue #20. | The app can take a mask with many segments for an 8-bit image; the user knows better. |
| 2026-11-20 | Several images in the Files list? | Not built. One image at a time; several masks. Issue #20. | It would touch viewport and room code other work is changing; the masks were the need. |
| 2026-11-19 | What do subtract and intersect mean between two segments? | The app offers only "Add" under Combine. `combine()` still takes all three. | A labelmap holds one segment per voxel, so two segments never overlap: subtract would never change anything and intersect would always empty the segment. |
| 2026-11-19 | Do grow, shrink and smooth count the edge of the volume as the edge of the segment? | No. Shrink and the opening half of smooth never wear a segment away from the edge of the scan; the closing half of smooth treats space past the edge as empty. | A segment cut off by the field of view continues outside it, and closing must not pull a segment towards the edge. |
| 2026-11-19 | What is a hole for "Fill holes"? | Space with no path to the edge of the volume through voxels that are not the segment. Only empty voxels in it are filled. | A pocket closed off by two segments together is not a hole in either, and another segment inside a cavity must be kept. |
| 2026-11-19 | When does a volume switch from mL to mm³? | Under 0.5 mL it is shown in mm³, otherwise in mL with one decimal. | Small lesions keep three significant figures; "0.8 mL" still reads as millilitres. |
| 2026-11-19 | What does "Paint over: Empty only" cover? | Any stroke that would change a voxel from one segment to another puts that voxel back. Erasing is not affected. | The setting is about painting; an eraser that silently skipped segments would surprise. |
| 2026-11-19 | Who handles wheel, trackpad and pinch input? | One listener of ours per viewport (`src/ui/gestureInput.ts`, logic in `src/viewer/gestures.ts`). Cornerstone's StackScroll and wheel-zoom bindings are removed. A mouse notch is one slice; a trackpad scroll is a distance turned into slices. | Cornerstone moves one slice per wheel event and drops events under one pixel, which only suits a notched mouse. Issue #18. |
| 2026-11-19 | Where do mouse and trackpad preferences go, given the five Settings sections? | A sixth section, "Mouse and trackpad", after Appearance. Adds to the 2026-11-19 row on where preferences live. | Requested in issue #18; six rows of input settings do not fit under Appearance. |
| 2026-11-19 | With two-finger scroll set to pan, how are slices changed on a trackpad? | Shift+scroll changes slice at normal speed. The mouse wheel is not affected by the setting. | Ctrl/Cmd already mean zoom and Alt means brush size; Shift is the one left. Issue #18. |
| 2026-11-20 | What is the smallest brush? | The radius given to the tools never drops below 0.505 × the diagonal of a voxel in the plane of the view in use, so a click always paints the voxel under the cursor (one to four voxels). The size control starts at the smallest diameter that paints on the image's finest plane, rounded up to 0.1 mm. Sizes keep one decimal below 5 mm. | A voxel is painted when its centre is inside the brush; at 1 mm on a 1 mm scan most clicks painted nothing. Half a voxel side is not enough: a cursor on a voxel corner is 0.71 of a side from the nearest centre. Issue #21. |
| 2026-11-20 | How do popovers avoid showing pieces of the rows behind them? | Popovers in the segments panel (row menu, colour palette, amount forms, combine) are as wide as the rows, and the room popover takes the panel's inner width when the panel is open. No scrim. | The other option, dimming the panel while one is open, adds a flash to every menu. Full width covers the rows edge to edge and nothing moves. |
| 2026-11-20 | What leaves a narrow status bar first? | Whole items, in this order: size, zoom, window, segment under the cursor, value, position. The save and recovery state stays in full. | Clipped text read as broken ("recov…"), and the save state is the one thing in the bar that asks for attention. |
| 2026-11-20 | Do tooltips move as they appear? | No. Opacity only, in after the 400 ms delay, and gone at once on leaving. This supersedes the 4px offset for tooltips in DESIGN.md 5; menus and popovers keep it. | A transform on 12px text renders soft in WebKit while it moves, and a tooltip that fades out is still half visible over the next button. Issue #21. |
| 2026-11-20 | What happens on a click in the 3D view with an edit tool? | A toast: "Paint on the axial, sagittal or coronal view. The 3D view shows the result." At most once every 1.5 s; dragging still rotates. | The 3D view cannot be painted on, and doing nothing looked like a dead tool. Issue #21. |
| 2026-11-19 | How is the real desktop app tested in CI? | Linux and Windows: WebDriver through `tauri-driver`, in `e2e-desktop/`. macOS: the Playwright suite in WebKit plus a self-test the built app runs on itself. | There is no WebDriver for WKWebView. |
| 2026-11-19 | How do tests get past the native save dialog? | `W_E2E_SAVE_DIR`, read at launch, makes `pick_save_path` return a path in that folder without a dialog. `W_SELFTEST` makes the app test itself and quit. Both are in every build and do nothing unless set. | A native dialog cannot be driven; a separate test build would not be the app that ships. |
| 2026-11-19 | Which address does the host of a room hosted by the app use? | The host connects over `127.0.0.1`; the invite link carries the network address, or `127.0.0.1` with a note when there is none. | The host's own connection must not depend on a firewall or on the network being up. |
| 2026-11-19 | May CI use real scans? | One LUNA16 chest CT with its lung mask (CC BY 4.0, public and de-identified), range-fetched from Zenodo and cached, in its own job. Nothing from it enters the repository. | The licence allows it, a single case is 31 MB, and it keeps real-data regressions visible. |
| 2026-11-21 | Which scissors does the app's own outline code cut with? | Freehand always; rectangle and circle when the action is Erase outside or the depth is All slices. A rectangle or circle on one slice, and the sphere, stay with Cornerstone's scissors. | The existing rectangle and circle are covered by the desktop and WebKit checks and behave well; only the new cases needed new code. |
| 2026-11-21 | What do the scissors erase? | The active segment only, for every shape, inside or outside. Strokes made by Cornerstone's scissors are corrected afterwards, the way "Empty only" is. The eraser brush still erases any segment. | The gap review asks for it, and "Erase outside, all slices" on every segment at once would be a way to lose a whole mask in one drag. |
| 2026-11-21 | Which voxels are inside an outline? | Those whose centre is inside, by the even-odd rule; a centre exactly on a shared edge belongs to one side only. Voxel rows are cut against the outline in the view's plane, so thick slices and tilted volumes need no special case. "This slice" is the layer of voxels nearest the plane on screen. | One rule for every view and grid; two shapes drawn edge to edge never both take or both miss a voxel. |
| 2026-11-21 | Scissors depth: is "± mm" built? | No. This slice and All slices only. | The task named those two. A third state needs a number field in a strip that is already full at 1024 wide. |
| 2026-11-21 | What does "Paint over: Only <segment>" cover? | Tool strokes are corrected afterwards: a voxel painted where the chosen segment was not is put back. The app's own fills (outline scissors, Fill between slices) only write where it is. Locked and hidden segments are never written over by those fills. Erasing is not limited. The choice goes back to Everything, with a toast, when its segment is deleted or becomes the active one. | Same mechanism as "Empty only", so every tool obeys it without a change to the tool. |
| 2026-11-21 | What does Fill between slices write over? | Empty voxels, or with "Only <segment>" the inside of that segment. With Everything it still fills empty voxels only. | An interpolated shape is a guess; it should not take voxels someone painted as another segment. |
| 2026-11-21 | How is a fill preview drawn, and when does it end? | From a second labelmap that is never the mask: the proposed voxels as diagonal stripes, two voxels wide, of the segment colour at two strengths, no outline. Apply works the fill out again from the mask as it is then. Another tool or segment, a stroke, saving, or closing cancels it. | Stripes cannot be mistaken for mask; recomputing on Apply respects edits a room member made meanwhile. |
| 2026-11-21 | Are Enter and Esc for the preview rebindable? | No. They are fixed keys, listed with the mouse actions in the shortcut list. `I` still starts it and can be rebound. | Enter and Esc are reserved in `shortcuts.ts`; a preview is a yes or no question like a dialog. |
| 2026-11-21 | Is "Smooth pixels" per view? | No. One remembered setting for the three slice views, switched from any view's menu. | A border judged on one plane is checked on the others; three switches would get out of step. |
| 2026-11-21 | How many segments can a split make? | At most 20 new ones, largest islands first; the rest stay in the segment. It asks first when it would make more than 5. Undo moves the voxels back and leaves the new, empty rows. | Model output can hold hundreds of specks; the list must stay usable. |
| 2026-11-21 | Why do the reference lines ignore some camera resets? | Adding a labelmap to a view makes Cornerstone reset the camera and restore it; its crosshairs answered the reset by sending every view to its middle slice. `LinkedLinesTool.followResets` is off while the fill preview is being added. | Showing a preview must not move the user off the slice they are looking at. |
